# ELECTRIC SYSTEM — بوابة التحميل والخدمات (V1)

صفحة ويب ثابتة عربية RTL، متجاوبة مع الجوال والكمبيوتر، تتضمن الشعار المستخرج من أيقونة تطبيق ELECTRIC SYSTEM المرفق بالمشروع، تحميل Android وiOS، إرشادات سلامة، تعريف بالنظام، نماذج طلب عبر واتساب، وصفحة QR لتوليد باركود صحيح بعد النشر.

## الملفات

- `index.html`, `styles.css`, `app.js`: واجهة الصفحة (لا تتطلب Flutter أو Android Studio).
- `assets/logo.png`: الشعار المستخرج من موارد تطبيق Android.
- `config.json`: عنوان خدمة الإصدارات ورقم واتساب الدعم.
- `qr.html`, `qr.js`, `qr-code-vendor.js`, `LICENSE-QR.txt`: إنشاء QR محلي داخل المتصفح من **رابط الموقع المنشور الحقيقي** وتصديره PNG.
- `supabase/functions/electric-public-downloads/index.ts`: دالة Edge Function **جديدة مستقلة** لقراءة آخر إصدار منشور من `electric_app_releases`. لا تلمس `electric-center-admin`.

## أولاً: النشر المجاني

### GitHub Pages

1. أنشئ مستودعاً عاماً خاصاً بالصفحة، مثلاً `electric-system-download`.
2. ارفع `index.html`, `styles.css`, `app.js`, `config.json`, `qr.html`, `qr.js`, `qr-code-vendor.js`, `LICENSE-QR.txt` ومجلد `assets` إلى **جذر** المستودع.
3. من `Settings → Pages` اختر `Deploy from a branch` ثم `main` والمجلد `/ (root)` واحفظ.
4. بعد أن ينشر GitHub الموقع، افتح عنوان الصفحة الحقيقي (مثل `https://YOUR_USERNAME.github.io/electric-system-download/`).
5. افتح `/qr.html` داخل الموقع المنشور. سيُظهر QR إلى `/index.html` تلقائياً. اضغط **حفظ الباركود PNG** ثم طباعته أو مشاركته.

### Netlify

يمكن رفع ملفات الواجهة الثابتة نفسها (دون مجلد `supabase`) إلى Netlify بنشر مجلد الموقع. لن تُعطى عنواناً مسبقاً؛ استخدم العنوان الفعلي بعد النشر لإنشاء QR.

## ثانياً: تشغيل التحديث التلقائي عبر Supabase

1. افتح Supabase الخاص بـ ELECTRIC SYSTEM.
2. افتح `Edge Functions` وأنشئ دالة **جديدة** باسم `electric-public-downloads`.
3. انسخ محتوى `supabase/functions/electric-public-downloads/index.ts` إلى ملف `index.ts` للدالة الجديدة وانشرها.
4. **أوقف Verify JWT لهذه الدالة العامة وحدها** حتى يتمكن الزائر غير المسجّل من استلام بيانات أحدث الإصدارات. لا تغيّر إعداد التحقق الخاص بدوال الإدارة أو التفعيل.
5. الدالة تقرأ فقط الصفوف ذات `is_published=true`, `app_type='center'`, `platform='android'` أو `'ios'` وبها `download_url` صالح. تختار الأعلى `build_number` وتعرض رقم الإصدار والرابط والحجم والملاحظات. مفتاح `SUPABASE_SERVICE_ROLE_KEY` يبقى داخل بيئة Supabase فقط ولا يوضع في الموقع.
6. تأكد أن آخر نسخة Android الحقيقية منشورة في `electric_app_releases` وبرابط HTTPS صحيح قبل أن تتوقع ظهور زر تحميل فعّال. لا تغيّر نسخة قاعدة البيانات بالحدس، ولا تنشر مسودة APK غير متحقق منها.
7. ملف `config.json` يحتوي سلفاً عنوان مشروع Supabase المعروف من `lib/main.dart`؛ اسم الدالة ضمن العنوان هو نفسه المطلوب (`electric-public-downloads`). إذا نقلت المشروع غيّر العنوان.
8. حالة iOS: **لا يوجد في البيانات المتاحة حالياً رابط رسمي iPhone**؛ لهذا يعرض الموقع «قريباً». يفعّل الزر تلقائياً في المستقبل فقط بعد نشر صف `platform='ios'` مع رابط رسمي صالح، إذا كانت قيود قاعدة البيانات تدعم هذه القيمة. لا تنشر APK للأيفون.

**تنبيه:** صفحة الويب تستطيع اكتشاف **الإصدار المنشور على Supabase** فقط. المتصفح لا يستطيع معرفة الإصدار المثبت على هاتف الزائر؛ التحقق من التحديثات الإلزامية داخل تطبيق Flutter يبقى منفصلاً.

## ثالثاً: تفعيل واتساب

أضف رقم دعمك في `config.json` مكان القيمة الفارغة، بصيغة دولية بدون `+` أو أصفار بداية، مثال **توضيحي فقط وليس رقماً حقيقياً**: `9647XXXXXXXXX`.

```json
"supportWhatsapp": "9647xxxxxxxxx"
```

بعد إدخال الرقم الصحيح يصبح نموذج «طلب تفعيل مركز»، «طلب خدمة فنية»، «الدعم الفني» قادراً على فتح واتساب برسالة جاهزة. العميل يراجع النص ويرسله بنفسه. إذا لم تضع الرقم، تبقى إمكانية **نسخ نص الطلب** متاحة ولا توجه المستخدم إلى رقم غير معروف.

## السلامة / الخصوصية / الإصدارات

- لا تخزن الصفحة كلمات مرور أو رموز تفعيل أو بيانات مستخدمين. نماذج طلب الدعم تعمل محلياً حتى فتح واتساب.
- احذر من وضع Supabase `service_role`, API secret, مفاتيح التشفير، أو حسابات المركز في المستودع العام.
- فقط البيانات العامة للإصدارات المنشورة تُرسل للمتصفح؛ لا تُظهر مسودات الإصدارات.
- تحديث الإصدار في Supabase يصبح ظاهراً على الصفحة عند إعادة التحقق دون تعديل HTML، بعد انتهاء التخزين المؤقت القصير.
- يجب رفع النسخة iOS إلى App Store / TestFlight أو توزيع رسمي متوافق أولاً، والتأكد من دعم `ios` في قيود `platform` بقاعدة البيانات.
- لا تُطبع QR قبل نشر الصفحة والتأكد أن الرابط يفتح من هاتف آخر.
- موقع المثال الذي طلب المستخدم محاكاته `https://ali-dhya96.github.io/bayt-alrashid/` تعذر فحصه مباشرة أثناء الإنشاء؛ هذا التصميم مستقل وغير منسوخ.
